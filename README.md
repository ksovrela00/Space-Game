# Solar Trader

Псевдо-3D космический симулятор в духе Elite: полёт от планеты к планете
внутри звёздной системы и стыковка со станциями. Чистый JavaScript,
ES-модули, Canvas 2D, свой 3D-движок. Сборка не нужна.

## Запуск

Зависимостей нет: `npm install` не нужен, бэкенда и сборки тоже. Нужен только
любой статический HTTP-сервер — ES-модули не работают из `file://`.

Если проект лежит в `htdocs` XAMPP, достаточно открыть:

```
http://localhost/space_game/
```

Без XAMPP годится что угодно, например из папки проекта:

```
python -m http.server 8080      # -> http://localhost:8080/
npx serve .                     # -> адрес выведет сам
php -S localhost:8080           # если есть PHP
```

Параметры в адресной строке:

- `?dev=1` — старт в 20 км от порта станции для быстрой проверки стыковки
  (сохранение при этом не читается);
- `?renderer=2d` — принудительно Canvas-2D-рендер вместо WebGL (для сравнения
  картинки и как запасной путь на старом железе).

## Перенос на другую машину

Копируется вся папка проекта как есть — ничего не генерируется и не собирается:

- `index.html`, `css/`, `js/` — сама игра, это всё, что нужно браузеру;
- `tools/`, `package.json` — headless-проверки (нужен Node 18+, лучше 20+);
- `README.md` — этот файл;
- `.claude/` — локальные настройки Claude Code, для игры не нужны.

Что **не** переносится:

- **Сохранение.** Оно лежит в `localStorage` браузера под ключом
  `solar_trader_save_v1` и привязано к домену. На новой машине игра начнётся
  с вылета из порта родной станции. Это не потеря прогресса в привычном
  смысле — сохраняются только позиция, корпус, цель и счётчик стыковок.
- **Git-история.** Репозитория в проекте нет, версионирование не заводилось.
  Если продолжать работу планируется на двух машинах, стоит сделать
  `git init` и завести remote — иначе синхронизация будет ручным копированием.

Проверка после переноса: открыть страницу (в консоли не должно быть ошибок,
на отладочном оверлее `~` — fps и координаты) и прогнать `node tools/test.mjs`.

## Статус

Сделано и проверено: полёт, звёздная система с планетами и лунами, круизный
ускоритель, навигация с автопилотом, ручная стыковка и докинг-компьютер,
крушения, карта системы, справка, два вида камеры, сохранение.

Не сделано (сознательно, следующий этап): торговля и деньги, бои и NPC,
галактика из нескольких систем с гиперпрыжками, посадка на поверхность
планет, звук.

Два отступления от первоначального замысла — их причины важны, если менять
масштабы или динамику:

- вместо ускорения времени сделан **круизный множитель только для корабля**
  (`js/game/cruise.js`): мировые часы идут в реальном темпе, поэтому планеты
  не носятся по орбитам, а перелёт всё равно занимает минуты;
- **орбитальные периоды — годы**, то есть тела практически стоят
  (`js/game/world.js`). Модель полёта не использует вращающуюся систему
  отсчёта, а планета, идущая по орбите быстрее корабля, делает стыковку
  невозможной: станция убегала бы из-под носа. Вращение планет и станций
  вокруг своей оси при этом хорошо заметно.

## Управление

| Клавиша | Действие |
|---|---|
| `W` / `S` | тангаж: нос вниз / вверх |
| `A` / `D` | рыскание влево / вправо |
| `Q` / `E` | крен влево / вправо |
| `↑` / `↓`, `←` / `→` | тангаж и крен (классическая схема Elite) |
| `Shift` / `Ctrl` | тяга больше / меньше |
| `X` / `F` | тяга в ноль / полная |
| `Tab` / `Shift+Tab` | следующая / предыдущая цель |
| `T` / `Y` | круизный ускоритель +/− |
| `J` | автопилот к выбранной цели |
| `C` | докинг-компьютер (ближе 120 км до станции) |
| `V` | кокпит ⇄ вид от 3-го лица |
| `M` / `H` / `~` | карта системы / справка / отладка |
| `Space` | вылет со станции, рестарт после крушения |

Обычный перелёт: `Tab` до нужной станции → `J`. Автопилот выводит к створу
порта и сам включает стыковку. Вручную: войти в щель порта носом вперёд,
относительная скорость ниже 0.28 км/с, крен согласован с вращением станции
(зелёные огни порта — сверху). Подсказка со створом и индикаторами
«ОСЬ / КРЕН / СКОР» появляется в верхней части экрана при подлёте.

## Устройство кода

```
index.html            два наложенных canvas (#screen — 3D, #hud — приборы)
                      + DOM-оверлеи (экраны станции, крушения, справки)
js/main.js            игровой цикл: фиксированный шаг физики 60 Гц, режимы, сейв,
                      выбор рендера (WebGL или Canvas 2D)
js/core/              vec3, базис (ортонормированная тройка), ГПСЧ, ввод
js/gl/                рендер на WebGL2: контекст, шейдеры, матрицы,
                      логарифмическая глубина, икосфера, процедурный рельеф,
                      сборка мешей планет, проходы сцены
js/render/            Canvas-2D-рендер (запасной путь) + камера, которой
                      пользуются оба рендера и HUD
js/models/            генераторы мешей: корпуса кораблей, станция «Кориолис»
js/game/              звёздная система, физика корабля, круиз, навигация,
                      автопилот, стыковка, машина состояний
js/ui/                HUD, экраны, карта системы, отладочный оверлей
tools/                headless-проверки (см. ниже)
```

Ключевые решения и их причины расписаны в комментариях к соответствующим
модулям — в частности, почему ориентация хранится тройкой векторов
(`js/core/basis.js`), почему планеты рисуются аналитически, а не полигонами
(`js/render/planetview.js`), почему орбитальные периоды огромны
(`js/game/world.js`) и почему наведение работает по угловой скорости, а не
по углу (`js/game/docking.js`).

Два решения, без которых WebGL на таких масштабах не работает, расписаны в
`js/gl/mat4.js`: координаты объектов уходят в шейдер как смещение ОТ КАМЕРЫ
(иначе float32 на орбите в миллионы километров теряет километры, и близкие
объекты дрожат), а глубина пишется логарифмически (иначе один буфер на
диапазон от 4 метров до сотен миллионов километров даёт z-fighting по всей
сцене).

## Проверки

Тесты работают в Node без браузера: DOM и canvas подменяются заглушками.

```
node tools/test.mjs     логика: мир, вращение, автопилот, стыковка, столкновения
node tools/gl.mjs       WebGL: икосфера, рельеф, LOD, матрицы, глубина, точность
                        float32 + прогон пути отрисовки через мок GL-контекста
node tools/smoke.mjs    реальные кадры main.js во всех режимах (ловит падения рендера)
node tools/shot.mjs     ASCII-«скриншоты»: растеризует вызовы canvas в текст
```

`tools/shot.mjs` полезен для проверки визуала Canvas-2D-пути: он показывает
фазы освещения планет, кольца, силуэт станции и створ порта прямо в консоли.

**Важное ограничение.** Пиксели WebGL автотестами не проверяются: ни Node, ни
ASCII-скриншотер не видят вывод GPU. `tools/gl.mjs` проверяет всё до драйвера —
геометрию, матрицы, отсутствие NaN в uniform, наличие draw-вызовов, рост LOD при
подлёте, — но то, как это выглядит, проверяется только глазами в браузере.
Поэтому Canvas-2D-рендер сохранён: `?renderer=2d` даёт эталон для сравнения.

## Точки расширения

Задел под продолжение уже заложен: `world.entities` — общий список объектов для
NPC-кораблей и снарядов, состояния в `js/game/state.js` расширяются новыми
экранами (рынок, снаряжение), система строится из seed, так что над ней
надстраивается галактика из нескольких систем с гиперпрыжками.
